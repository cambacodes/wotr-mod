## Request, placement, and saved lifecycle

Main registers the authored blueprint and the saved request/retry flags during Build, before a save restores their identities.
The callback reads raw native saved flags and live evidence instead of calling State recursively.
It requires an accepted, completed reply, no refusal, no closure, no completed visit, and twelve elapsed hours from the hour-plus-one acceptance timestamp.
Negative counters and invalid timestamps do not authorize a request.
Long arithmetic protects the elapsed-time calculation.
Observation preserves the same episode identity; only the explicit retry action advances it.

The exact registered first-words dialogue retains the request while open.
A different object with the same name does not.
Combat, another mode, scheduled dialogue, loading, unloading, disabled integration, or lost actor evidence withdraws authorization.
The update hook calls Tick before the enabled early return, and disabling also calls Tick.
Consequently, the source provides a path for native reevaluation after authorization is withdrawn.
Its successful Unity execution remains untested below.

Place preflights the native actor and locator, records the actor and request identity, unhides, rereads the current view, and only then moves.
It rechecks eligibility and group ownership after unhide.
Arrival requires the same saved actor/request, the authored fact playing, actual group ownership, non-dummy usable contact, and position within 1.5 metres of the native locator.
Acceptance or an unverified partial unhide does not set arrival.

AttemptPlacement keeps Failed false during verification so its own eligibility checks do not reject an in-progress successful attempt.
Its finally block marks every false or throwing attempt failed afterward.
That failure survives serialization and blocks the same episode.
A different retry episode cannot replace the previously bound actor.
Ordinary pre-action deferral remains eligible to resume without repeatedly advancing saved retry state.
Placed is not serialized and is reset on load and resume, forcing current arrival evidence to be checked again.
